# Earthcall audit — July 2026

Audit of the repository at `58ef81d` ("save system"). Everything below was
verified by building and running the code, not by reading alone: the C++ sources
were compiled with GCC 13 on Linux (macOS-only headers shimmed) and the full test
suite was executed under a virtual display.

Findings are ordered by consequence. Each says whether it was fixed on this
branch or left for a decision.

---

## 1. `Flow` laws silently did nothing on float properties — FIXED

`ActionNode::Kind::Flow` is the rate form of an authored law: `dp/dt = f(...)`,
integrated once per tick. Its executor read the current value and required the
`double` alternative of `PropertyValue`:

```cpp
if (std::holds_alternative<double>(current) && ...)
```

But the world registers its scalar properties as **`float`** — `position.y`,
scale, mass, and everything else spatial. Verified directly: reading
`position.y` off a fresh `Object` yields variant index 2 (`float`), not 3
(`double`). So the condition was false for every ordinary property, the `else`
branch returned, and the law wrote nothing — no error, no log line, no clue.

The sibling actions in the same file (`Add`, `Scale`, `Lerp`) already do this
correctly, via `propertyValueToNumber`, which accepts any numeric alternative
and lets `lawSetValue` coerce back to the slot's real type. `Flow` was the one
that didn't.

`tests/time_flow_test.cpp` has caught this the whole time — it asserts
`b.getPosition().y == 6.0` after integrating 3 units/second for 2 seconds, and
the actual value was `0.0`. The test is in `make test`, so `make test` was red.

**Fixed** in `src/ZonesOfEarth/AuthorsOfLaw/ActionModel.cpp` by reading the slot
numerically, matching `Add`/`Scale`/`Lerp`. `time_flow_test` now passes.

## 2. `action_spawn_test` asked for a concept that never existed — FIXED

The test built an `ObjectConcept("test-concept")` and then set
`node.conceptId = "test-concept"`. But that string is the concept's *display
name*; `ConceptRegistry::find` keys on the **identifier**, which
`ObjectConcept`'s constructor mints as `"concept-N"`. The lookup returned null,
`Spawn` returned early, and the assertion `size() == 1` failed.

This is a defect in the test, not the product — but it means the second of the
two tests wired into `make test` was also red.

**Fixed** in `tests/action_spawn_test.cpp` (ask for `concept->getIdentifier()`).

> With both fixed, the suite is **23/23 green**. Before this branch it was 20/22
> — and nothing in the repo would have told you, because there is no CI.

## 3. Whitelist bypass in `SecurityManager::isURLWhitelisted` — FIXED

The whitelist is what stands between an embedded `WKWebView` and the open
internet. It matched with a raw string prefix:

```cpp
if (url.find(domain) == 0) return true;
```

With an entry of `https://trusted.earthcall.com`, all of these passed:

| URL | Real host |
|---|---|
| `https://trusted.earthcall.com.attacker.test/` | `attacker.test` |
| `https://trusted.earthcall.commercial.test/` | `commercial.test` |
| `https://trusted.earthcall.com@attacker.test/` | `attacker.test` |

The first is the standard suffix-gluing bypass; the third smuggles the expected
name into the userinfo field, where it has no authority at all. Note that
`SecurityLevel::PARANOID` *installs* `https://trusted.earthcall.com` as the
whitelist, so the strictest configured level was the one most exposed to this.

**Fixed**: matching now parses the host out of the URL (dropping userinfo and
port, lowercasing) and accepts an exact host or a genuine dot-delimited
subdomain. New `tests/security_url_test.cpp` pins all of the above, and is wired
into `make test`.

## 4. `backend-python/app.py` did not parse at all — FIXED

```python
return render_template('index.html'
```

An unclosed call — `python3 -m py_compile` fails outright, so the Flask app
could never have started. Also `app.run(debug=True)`, which enables the Werkzeug
interactive debugger; anyone who can reach that port can execute arbitrary code
on the host.

**Fixed**: closed the call, and debug now requires `EARTHCALL_DEBUG=1` rather
than being on by default.

## 5. A missing `#include <string>` made a header non-portable — FIXED

`src/OurVerse/AdvancedFacePaint.hpp` declares `std::string message = "";` while
including only `<glm/glm.hpp>`, `<vector>`, and `<memory>`. It compiles under
libc++ (macOS) purely by transitive luck; under libstdc++ it is a hard error
(`field 'message' has incomplete type`). This was the only file in the whole
tree that failed to compile on a second toolchain.

**Fixed**: added the include.

## 6. The law hot path printed four debug lines per property write — FIXED

`lawSetValue` in `MathBinding.hpp` — the funnel every law write passes through —
ran unconditional `std::cout << ... << std::endl`. That's a flush per line, per
property, per target, per law, per tick. Running one test produced 72 trace
lines from a handful of law applications; a populated world at 60fps is a
different order of magnitude, and `std::endl` forces a synchronized flush each
time.

**Fixed**: the trace is retained but gated behind `EARTHCALL_TRACE_LAWSET=1`.
Default runs are silent; verified both ways.

## 7. Repository hygiene: 2,103 tracked files, most of them not source — FIXED

Untracked (files remain on disk; `.gitignore` files added at the repo root and
in `sight-cpp/`):

| What | Count / size |
|---|---|
| `venv/` — a committed Python 3.9 virtualenv | 827 files, 13 MB |
| `build/` plus stray `.o`/`.d` objects | 302 files |
| `src/Singularity/Core/EventBus.hpp.gch` | 14.6 MB |
| `tests/action_spawn_test.dSYM/` | 67 MB |
| `.DS_Store` | 13 files |

Tracked file count went **2,103 → 958**.

The `.gch` deserves its own note: when a precompiled header sits next to its
`.hpp`, GCC and Clang *prefer the `.gch`*. A stale one either fails the build in
a way that looks unrelated to the change you made, or — if it validates — builds
the project against declarations that no longer exist in the source. It is the
kind of artifact that costs an afternoon exactly once.

Because `venv/` is no longer tracked, `backend-python/requirements.txt` was added
so the environment is reproducible. Note that `agent/earthcall_agent.py` imports
`playwright`, `pyautogui`, and `pygetwindow` — **none of which were in the
committed virtualenv**, so that script could not have run as shipped. They are
listed in the new requirements file.

## Left for you to decide

### A. Save files are 1.9 GB, and half of every one is dead weight

`sight-cpp/saves/` holds 318 tracked JSON files totalling 1.9 GB; the largest is
98 MB. Breaking down a representative 80 MB quicksave:

```
38.53 MB  zones          (zones[].world.objects — 292 objects)
38.26 MB  objects        (top-level array — 290 objects)
 2.38 MB  playerBody
 0.01 MB  everything else
```

Two things are wrong here.

**The `objects` array is written and never read.** `Game::saveStateWithLog`
(`GameSaveLoad.cpp:160`) calls `buildSaveJson()` — which already serializes every
zone's world, objects included — and then appends a second copy of the active
zone's objects under a top-level `"objects"` key. `Game::loadState` never looks
at that key; it reads objects only from `zones[].world`. So roughly **half of
every quicksave is written to disk and then ignored on load.** Deleting those
twelve lines halves save size and save time with no behavioural change. I left
it alone because "the log variant" may be feeding a tool I can't see from here —
but if it isn't, this is the single cheapest win in the repo.

**Face textures dominate the rest.** 38 MB of the 38.5 MB of real object data is
`faceTextures`, stored as Base64 of raw RGBA8 — about 131 KB per object. The
sample data is a flat single colour repeated thousands of times (`ff0000ff` over
and over), i.e. untouched default textures being persisted at full size. Two
independent fixes: skip faces that are still at their default fill, and run the
pixels through zlib/PNG before Base64 (Base64 itself adds 33% on top of already
uncompressed data). Either alone would cut the files by an order of magnitude.

I did not remove `saves/` from tracking — it is your data and that is your call.
If you want it out:

```sh
git rm -r --cached sight-cpp/saves && echo 'sight-cpp/saves/' >> sight-cpp/.gitignore
```

(That stops future growth. The 241 MB already in `.git` needs a history rewrite
to reclaim, which is worth doing separately and deliberately.)

### B. The WebView's URL whitelist is only enforced on the first load

`WebViewBridge` in `RealWebView.cpp` declares conformance to
`<WKNavigationDelegate>` and implements `didFinishNavigation` and
`didFailNavigation` — but **not** `decidePolicyForNavigationAction:`, which is
the only hook that can actually refuse a navigation. `validateURL` runs once,
against `_config.url`, at init. After that a link, a redirect, or one line of
`window.location` takes the WebView anywhere it likes, whitelist notwithstanding.
Fixing #3 above raises the quality of the gate; this determines how often the
gate is consulted at all.

Related, in the same file and unverifiable from Linux (macOS-only Objective-C++,
so please confirm on your Mac):

- **The bridge is never installed as the navigation delegate.** There is no
  `setNavigationDelegate:` anywhere. As written, `didFinishNavigation` never
  fires, so `_loaded` stays `false` forever and `isLoaded()` always lies. (No
  caller depends on it today, which is why nobody has noticed.)
- **`__weak RealWebView* weakSelf = this;`** — `RealWebView` is a C++ class, not
  an Objective-C object, so it cannot have a weak reference. Without ARC the
  qualifier is simply ignored and the block captures a raw `this`. The blocks
  outlive the C++ object if the bridge does, and `if (weakSelf)` will never be
  false, so the guard reads as protection while providing none.

### C. Security policy that is weaker than it looks

- `generateSandboxPolicy()` returns `allow-scripts allow-same-origin`. That
  specific pair is self-defeating: content served from the same origin can reach
  into the parent document and strip its own sandbox attribute. If the framed
  content is same-origin, drop `allow-scripts`; if it needs scripts, serve it
  from a distinct origin and drop `allow-same-origin`.
- `generateCSP()` emits `script-src 'self' 'unsafe-inline'`. `'unsafe-inline'`
  re-permits exactly the injection class CSP exists to stop. Use a per-load
  nonce or hash.
- `SecurityLevel::HIGH` is byte-for-byte `MEDIUM` plus `logAllEvents`, and
  `PARANOID` adds only a default whitelist. Three of the four levels are
  effectively one level; either differentiate them or collapse the enum, because
  a setting that promises tightening and doesn't is worse than no setting.
- `_maliciousPatterns` is populated in `_initializePatterns()` and consumed only
  by `SecurityManager.cpp:519`; confirm that path is actually reached, or drop
  the list.
- `isURLBlacklisted` substring-matches the whole URL, so a blacklisted domain
  appearing anywhere — including in a query parameter of an unrelated host —
  blocks the request. It fails closed, so it is a usability bug rather than a
  hole, but it should match on host like the whitelist now does.

### D. No CI, and most tests need a display

There is no `.github/workflows` anywhere in the repo. Combined with two tests
that were red at HEAD, nothing was watching.

17 of the 23 tests call `glfwInit()` and abort when it fails, so they need a
window server. They run fine under `xvfb-run` on Linux (that is how this audit
executed them) but that is not obvious from anything written down. Two options:
add a GitHub Actions job on macOS, or split the tests that genuinely exercise GL
from the ones that only inherited the boilerplate — most of the law and
serialization tests never touch a GL call.

### E. Smaller things

- **No README.** Nothing at the repo root or in `sight-cpp/` says what Earthcall
  is or how to build it. `docs/` holds 25 good architecture documents with no
  entry point pointing at them.
- **Portability.** 11 files hardcode `<OpenGL/gl.h>` / `<GLFW/glfw3.h>` with no
  `__APPLE__` guard, and the `Makefile` hardcodes `/opt/homebrew` paths and
  `-framework` flags. That is a legitimate choice for a macOS-only project — but
  it means no second compiler ever sees this code, which is how #5 survived.
- **`EventBus::_running` is a plain `bool`** read by `shutdown()` outside any
  lock and written under `_queueMutex`. A data race by the letter of the model;
  make it `std::atomic<bool>`.
- **`publishAsync` copies the event but not its referents.** `ECA::Event` holds
  raw `Singular*`. A queued job that runs after its subject is destroyed is a
  use-after-free. Only `EventHandler.hpp:55` forwards to it and nothing calls
  that today, so it is latent — worth a comment or a weak handle before it gets
  its first real caller.
- **`GameSaveLoad.cpp:314`** does `const auto& tj = lj["target"];` with no
  `contains` guard. An older save without that key throws; the enclosing `stage`
  lambda catches it, but the throw aborts the whole physics-law loop, so one
  malformed law silently drops every law after it.
- **`src/Legacy Depricated/`** — misspelled, and excluded from the build only
  incidentally (the `Makefile` filters `main.cpp` by name). 1,670 lines of dead
  code that still gets grep hits.
- **imgui is vendored at `1.92.0 WIP`** — a work-in-progress snapshot rather
  than a release, with all upstream examples and platform projects included.
  Pinning a tagged release would make updates tractable.
- **Compiler warnings are otherwise clean.** A full `-Wall -Wextra` pass over
  263 files produced only 59 `-Wunused-parameter` and a handful of cosmetic
  hits. The `-Wmisleading-indentation` warnings are all the `if (!up) continue;
  Object* obj = up.get();` idiom and are false positives. `LawGraphWindow.cpp:1010`
  has a genuine `-Wswitch` gap: six `ActionNode::Kind` values (`Create`,
  `AddProperty`, `AddElement`, `RemoveProperty`, `RemoveElement`, `Destroy`) are
  unhandled, so those action kinds render as nothing in the law graph.

xvfb-run -a ./<test_name>
