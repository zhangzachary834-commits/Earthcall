# Addendum: Integrating Authored Pixel Identity and GPU Micro-Mastery

**Scope:** Relationship between an authored identity doctrine and a proposed GPU execution architecture. The proposal is not an implementation certificate.

[Pixels: substrate, process, and authored identity](../architecture/ontology/PIXEL_SUBSTRATE_PROCESS_AND_AUTHORED_IDENTITY.md) distinguishes three coexisting perspectives: addressable samples or regions with Properties; manifestations of authored acts; and selected regions given identity by a Person through an appropriate Singular and its Properties and Relations. These are not three mandatory pipeline stages. A dense framebuffer does not require one Singular per sample, and a substrate coordinate does not itself establish durable identity.

[Native GPU OntoMath](../architecture/Singularity/NATIVE_GPU_ONTOMATH.md) proposes replacing structural WGSL regeneration with an interpreter for flattened OntoMath expressions in GPU storage buffers. That could change the cost of authored structural edits, but the source describes a **frontier**. Current OntoMath Screen integration still generates WGSL for structural AST changes. Do not treat the proposed interpreter, a single universal field, zero overdraw, or unlimited dynamic complexity as deployed and measured capabilities.

**Architectural connection:** A future GPU evaluator could manifest mathematical fields while the Person-authored Law/Property/Relation layer supplies meaning. The execution substrate must not silently assign identity, invent a universal pixel locator, or collapse the distinction between an authored act and a sampled observation.

**Evidence boundary:** The pixel doctrine records bounded direct-Screen witnesses and explicitly leaves general substrate correspondence, remapping, composition, and identity defaults open. Any implementation must define address context, temporal context, authored causation, and authorization, then measure its claimed performance separately.
