
Bugs:
1. ✅ **The self-lifting floor** — done and verified (2026-08-14): Fixed ungrounded list index fallbacks in `World.cpp`/`Ourverse.cpp`, fixed origin vs. `supportOffset` clamping in `Physics.cpp`, and filtered ground by `baseline` attribute in collision loop; guarded by `tests/ground_plane_test.cpp`. Open sub-issue: `Tool::ShapeGenerator3D` cursor hit fallback on miss. See [Specific Tasks/Self_Lifting_Floor_Bug.md](Specific%20Tasks/Self_Lifting_Floor_Bug.md).
2. ✅ **Concept newborns all shared one identifier** — done and verified (2026-08-17): `ObjectConcept::instantiate` named each newborn `<conceptId>.member-<slot>` (added 2026-08-16, `790c5c85`, replacing the generated `object-N`). A slot is not an identity: every spawn of a concept produced beings answering to the same name, and every identifier lookup in the engine is first-match (`World::removeObject`, `Formation::hasMember`, `Serialization.cpp`'s reattachment), so deleting one spawned cube by name removed an arbitrary sibling. Newborns are now named by concept **and birth** via `ObjectIdentity::generateConceptMemberId`, drawing the birth number from the same counter as `generateObjectId`; `claimIdentifierAtLeast` learned the `.birth-N.` form so a reloaded world cannot reissue a live identity. Guarded by `tests/shape_generator_law_test.cpp`.
3. ✅ **Double spawn: the law and the developer bypass both fired off one click** — done (2026-08-17), verified by build and inspection, NOT in-app. `Tool.hpp` states the contract — "so the two paths never both fire off one click" — and nothing enforced it: `Tool::ShapeGenerator3D` never checked `active3DMode`. Dormant while the law could not fire; live the moment it could, so an armed click made two objects (one via `Law::applyTo`, one via the bypass), and an *unarmed* click with the developer window open still spawned one. Added the `active3DMode == "Create"` guard, an `ImGui::GetIO().WantCaptureMouse` guard (the bypass polls GLFW directly, so this window's own buttons spawned cubes behind themselves), and moved the click-edge tracker above both gates so a gate opening mid-hold cannot read a held button as a fresh press. **Needs a human click to confirm** — see Feature-sized item 2. Open sibling: the same early-return is why the armed law now places at the origin (audit 1.1); loading `saves/tests/shape_generator_3d_law.json` still double-spawns via a second being `law-3` (audit 1.2). See [SHAPE_GENERATOR_LAW_AUDIT_2026-08-18.md](../../../audits/SHAPE_GENERATOR_LAW_AUDIT_2026-08-18.md).
4. **Armed Shape Generator 3D law spawns at the origin** — open (2026-08-18): `updatePlacement` has one runtime caller, `Tool::ShapeGenerator3D`, which returns before that call when `active3DMode == "Create"`. The law reads a live identity transform and Spawn treats it as success. Reproduced by `scratch/probes/shape_generator_law_audit_probe.cpp`.
5. **Test-save twin `law-3` double-spawns beside the boot first mover** — open (2026-08-18): `LawManager::loadFromJson` keeps `shape-generator-3d-law` and adds the seed's authored copy. `BUILD_AND_ENVIRONMENT.md` currently tells people to load that file.
