   **RESOLVED — Zach clicked a pawn in the running app and it moved (2026-08-27).** The gesture work above was real and stays; it was not the last defect. Actual root cause, found by Claude Opus 5 after Zach reported that the pawn click *did* register as `object-clicked` while Law Author showed `conditions failed -> piece-white-pawn`: **the Chess zone was running with zero formation relations**, so `instance-of category.chess.piece` was false for every piece all session. Two things in sequence — (1) `Engine::initLogic` calls `hydrateFromZoneStore()` (`EngineInit.cpp:193`) before any world loads, and categories are WORLD data loaded only in `loadState`, so hydration binds Chess's 38 relations while `category.chess.piece` does not exist yet and `Formation::add` REFUSES every `instance-of` edge with unbound endpoints; (2) `loadState`'s `admitFromJson` then found Chess **live** and returned without merging the session zone JSON, so nothing retried. This is **this bug (#7) through the one door its 08-24 fix did not cover** — that fix made `applyFormationRelations` always run *on load*, but this path never called `applyZoneJson`. Symptoms follow exactly: the board passes `law-chess-click` via the `isBoard` **property**, a piece has only the **relation** branch left and fails; `law-chess-select` never selects (no lift, no move); and `law-chess-drag-drop` (condition `hoveredId != ""`, no piece test) genuinely fires its action nodes into a world where nothing is selected — which is why Zach saw "sequence/publish executed on piece-white-pawn" with no movement. **Fix:** `admitFromJson` now merges the session JSON into a live zone too — `applyZoneJson(*live, zj, replaceObjects=snapshotRestore)`, the same remedy the store-hit branch has had since 08-24. **Why five sessions of green tests missed it: no test had ever booted the way the app boots** — a test process has no live zones, so it takes the store-hit branch and categories are loaded by then. Guarded by new `tests/zones/zone_boot_hydration_relations_test.cpp`, confirmed RED without the fix (relations = 0, 4 of 6 checks fail). Suite 72/73 (#11 is the only failure).
