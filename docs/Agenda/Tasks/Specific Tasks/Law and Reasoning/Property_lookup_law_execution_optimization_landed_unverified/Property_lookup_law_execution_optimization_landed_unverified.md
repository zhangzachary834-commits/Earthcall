**Property lookup / law execution optimization — landed, unverified, with one blocker.** (String interning proposed by Antigravity (Gemini 3.1 Pro) 2026-09-01; implemented by Claude Sonnet 4.5 in `a8a38e02`; reviewed by Claude Opus 5, session `01Qq5ryb6Nz4GdqcTxtfv9JN`, 2026-09-02 — replies appended in-file to each of the five documents.) String interning + Structure-of-Arrays property registry shipped: `Singularity/Core/StringId.{hpp,cpp}`, parallel `_propertyNames`/`_propertyRegistry` (`Singular.hpp:190-191`), `unordered_map<StringId, PropertyValue>` for authored state (`:195`), four new tests. The larger win is uncommitted: `lawGetValue`/`lawSetValue` no longer copy a `PropertyPath remainder` (a `std::vector<std::string>` heap-allocated per target, per law, per frame) — replaced by a `std::size_t startIndex`. Open, in order:
  1. **BLOCKER — six debug `printf`s in the hot path**, uncommitted, `PropertyPath.cpp:137, 152, 240, 266, 272, 281`. `:137` is unconditional and its message is false (it fires on *successful* resolves); `:152` calls `found->value()`, constructing a `PropertyValue`, only to print a flag. One unbuffered stdio call per property resolution inverts the whole optimization by ~3 orders of magnitude. **Nothing measured from this tree means anything until these are swept.**
  2. **No measurement exists.** Three documents argue a performance case with zero numbers from Earthcall; the "~300-500 vs ~15-30 cycles" figures are estimates, and the doc set contradicts itself on the cost of an SoA scan by an order of magnitude. Owed: `ctest` (reconfigure first — tests are globbed at `CMakeLists.txt:299`) and a `frame_lag_test` before/after.
  3. **Interner/main-thread race.** `StringId.hpp:76-80` asserts all property access is main-thread; `WebSocketServer::on_message` (bound `:922`, worker `:938`, no dispatch to main) calls `PropertyPath::parse` and `setValue` at `:320`. Pre-existing race on being state, now enlarged to a global one — `intern()` mutates a process-wide map/vector and `resolve()` returns a reference into a vector that can reallocate. Fix by deferring websocket commands to the main thread (also the right fix for the older race), or `std::deque` + `std::shared_mutex` in the interner. **No test in `tests/` uses `std::thread`.**
  4. **Phase 5 of interning:** `notifyPropertyChanged` still takes `const std::string&`, so `Singular.cpp:297` resolves the id back to a string on every authored-property write — still allocating on the hot path. The comment there already admits it.
  5. **`testSetValueZeroAllocation` (`property_path_precalc_test.cpp:163`) measures no allocations** — it asserts only that `setValue` works. Give it teeth (count via overridden `operator new`) or rename it; as written a regression reintroducing hot-path allocation passes green.
  6. `PropertyPath::parse` must never reach a per-frame path — it interns $O(S^2)$ sub-paths. True today across all 87 call sites, by accident rather than construction. Say so on `parse`.
  7. `StringInterner::clear()` resets the id counter, so ids are reused for *different* strings. Safe in standalone test binaries; catastrophic if ever called with a world loaded. Wants a stronger guard than a comment.
