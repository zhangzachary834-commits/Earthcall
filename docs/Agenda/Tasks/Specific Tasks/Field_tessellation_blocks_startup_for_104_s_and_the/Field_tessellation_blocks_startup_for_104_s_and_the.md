**Field tessellation blocks startup for ~104 s, and the resolution policy is the cause.** (opened 2026-08-28 by Zach, diagnosing "Earthcall is not responding" in Finder.) Full plan, with measurements and phase ordering: [FIELD_TESSELLATION_SCALING_PLAN.md](../../../../plans/FIELD_TESSELLATION_SCALING_PLAN.md). `saves/zones/NoiseFloorWorld/zone.json` holds one `SdfPrim::Expr` object at `fieldExtent (1000, 30, 1000)`. `Object::rebuildGeometryCaches` (`ObjectCollision.cpp:213`) sizes the marching-tet grid as `clamp(extent / 5, 24, 128)`, so that extent pins x and z to the **128 ceiling** — 2.36 M tets, 924 528 triangles — and it runs on the **main thread inside zone hydration**, so macOS marks the window unresponsive for the duration. Extent is the wrong input: a ground plane's box size says nothing about its feature size. Three parts, none done:
  1. ~~**Budget resolution by feature size or triangle count, not by `extent`.**~~ **PARTLY DONE 2026-08-28** (Gemini) — a global cell budget (1a) replaced the per-axis clamp, bounding the cost. Still open: **1b** the ⚑ AUTHOR-owned authored cell size, and **1c** sparse surface-following tessellation, which is what makes the sampling *right* rather than merely bounded — both planned in [SPARSE_FIELD_TESSELLATION_PLAN.md](../../../../plans/SPARSE_FIELD_TESSELLATION_PLAN.md).
  2. ~~**Get tessellation off the hydration path**~~ **DONE 2026-08-28** (Gemini) — `setFieldShape` marks the mesh dirty and returns; `rebuildFieldMesh()` runs on first consumer. Hydration cost for the noise floor went **~104 s → 0.4 ms**, first touch **1.15 s**. App startup **106.3 s → 2.7 s**; `frame_lag_test` **105.7 s failing → 3.7 s passing**.
  4. **Normals from the presampled grid** — **DONE 2026-08-28** (Gemini), removing ~97% of `evalSdf` calls. Review found the gradients were not divided by per-axis cell spacing, aiming normals up to **23° wrong** on an exact plane; fixed, with a direction check added to `geometry_ontomath_test`.
  5. **Per-frame collision AABB** — **DONE 2026-08-28** (Gemini): `_localMin`/`_localMax` are populated and `updateCollisionZone` transforms 8 corners with a transform/revision cache. Review found polyhedra keep the `±0.5` default because no polyhedron mutation point calls `rebuildGeometryCaches`, silently under-sizing their zones; fixed by reading the vertices in that case.
  3. ~~Kill the per-sample allocation in the OntoMath interpreter.~~ **DONE 2026-08-28** — `MathNode::evaluate`'s `Op::ScalarLeaf` projected the *whole* variable environment into a fresh `std::map` on every evaluation, and `geom::evalLeaf` rebuilt a 4-entry `std::map<std::string, PropertyValue>` per sample. For this tree (six constant literals x four variables) that was ~24 red-black-tree inserts per SDF sample, times millions of samples. ScalarLeaf now binds only the variables its terms actually mention (a constant form binds none); evalLeaf reuses one per-thread buffer. Measured on the real save: **108.1 s -> 64.3 s** for the same 924 528 triangles. Still far too slow — that is item 1's job.
