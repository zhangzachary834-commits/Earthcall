✅ **Fix the build again: a Jules-bot CMake refactor regressed both fixes above, plus a dead `#include <GL/gl.h>`** — done and verified (2026-09-01). `36fb621f` ("Add support and ImGui editor for MathNode", presumably chasing Linux CI) rewrote large parts of `CMakeLists.txt`'s top, and in doing so: (1) reintroduced the same macOS `uuid` break the entry above already fixed, this time via `find_library(UUID_LIB uuid)` used **unconditionally** in `earthcall_core`'s link list and in one test-target branch — `UUID_LIB` is `NOTFOUND` on macOS (no separate libuuid; symbols ship in libSystem), and CMake refuses to *generate* at all when a `NOTFOUND` variable is referenced unconditionally in `target_link_libraries`, so this was a harder failure than a compile error — `cmake -S . -B build` itself aborted with "used in this project but they are set to NOTFOUND" before any compilation. Moved `${UUID_LIB}` inside the existing `if (NOT APPLE)` guard (with a `message(FATAL_ERROR ...)` if still not found there) and dropped the now-redundant explicit `${UUID_LIB}` from the test-target branch, which already inherits it transitively through `earthcall_core`'s `PUBLIC` link. (2) The same commit swapped `earthcall_core`'s `OpenSSL::SSL`/`OpenSSL::Crypto` (proper CMake imported targets, which is how `OPENSSL_INCLUDE_DIR` reaches every translation unit) for the raw `${OPENSSL_LIBRARIES}` path list — same `.a` files, but no `INTERFACE_INCLUDE_DIRECTORIES`, so `openssl/rand.h` stopped resolving anywhere in `earthcall_core` (`src/Identity/Claim.cpp`, `KeyStore.cpp`, `KeyPair.cpp`, `SingularId.cpp`). Reverted to linking the imported targets. (3) Unrelated to that CMake commit: `src/Singularity/Screen/Camera.hpp` gained a bare `#include <GL/gl.h>` in the same MathNode-editor commit, which isn't the macOS OpenGL header path (`<OpenGL/gl.h>`, the convention already established in `OpenGLRenderer.cpp`/`GluCompat.cpp`) — and, checked, the file doesn't reference any GL symbol at all, so removed the include rather than fixing its path. **Verified**: fresh `cmake -S . -B build ...` configures and generates without error; `cmake --build build -j8` exits 0, zero `error:` lines; `ctest --test-dir build --output-on-failure -j4` is 82 registered, 81 pass (one more test than the prior entry — the tree grew in between — same single pre-existing `smooth_tessellation_cache_test` failure, nothing else).
