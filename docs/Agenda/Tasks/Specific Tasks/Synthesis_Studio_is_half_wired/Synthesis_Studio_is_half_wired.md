  - ✅ **FIXED 2026-09-02 (same session).** All of the below are repaired and verified: `cmake --build build -j8` clean, `ctest` 86/89 (failures: `smooth_tessellation_cache_test` pre-existing Bugs.md #11; `substrate_split_test` pre-existing, verified failing on a stashed baseline; `frame_lag_test` — a real regression I introduced, see Performance below). `earthcall_webgpu` builds, boots and runs. Full account in the audit's **REPAIR PASS** section. Fixing it surfaced **six engine defects the audit missed by reading**, three of which silently broke every authored world in the tree:
    - **Property lookups returned the WRONG property, engine-wide.** `Singular::registerTelosProperty` and `findProperty`'s dynamic fallback each pushed a name into `_propertyNames` *and* called `registerProperty`, which pushes to both parallel arrays — so `_propertyNames` ran one longer than `_propertyRegistry` and the index-paired scan resolved every property registered after `telos` to the one before it. `registerTelosProperty` runs for every being. Symptom: an authored property read correctly ONCE and then stopped; the studio's chord pad answered `isChordPad == true` on the first click and false forever after.
    - **`listProperties()` omitted every authored property**, so `LawManager::seedStateFacts` asserted no `property-state` fact for one, so **a `WhileTrue` law conditioned on an authored property never fired for any being** — every continuous law in every authored world. Also made authored properties invisible to inspection until touched (Refusal 6).
    - **`relation-state` facts were filtered for by `compileToRete` and never produced by anything**, so a `Related` condition in a continuous law compiled to a terminal no fact could reach — and a law with terminals never falls through to the sweep. Every "every instance of this category, every tick" law was deaf.
    - **The Rete alpha filter read a qualified root as a property name.** `@state.studio.themeNight` → attribute `"@state"`, which no fact carries, so the alpha rejected every fact. Fixed by *dropping* qualified-root conjuncts from the index (terminals are a candidate filter; `applyTo` re-checks the full tree) rather than refusing the law an index, which would put every channel-reading law on the full sweep 60×/s. A qualified-root **disjunct** still takes no index — dropping it would narrow.
    - **`Relation` dereferenced destroyed endpoints.** `aId()`/`bId()` call a virtual through raw pointers; a being can leave the world while relations point at it (`control_patterns_test` does it deliberately). `__cxa_pure_virtual` from a read, in every graph walk. New `RelationManager::forgetBeingEverywhere` drops the pointer and keeps the name. Anchored on the manager, not on `Relation` — relations are value-copied and a per-relation registry both misses copies and races static teardown (both tried, both crashed).
    - **Six debug `printf`s on the property hot path** in `PropertyPath::resolve`/`setValue`, two of them printing on the success path. Leftovers from the string-interning work.
    - **Save format:** a `vec3` PropertyValue serializes as `{"t":"vec3","x":..,"y":..,"z":..}`, NOT `{"t":"vec3","v":[…]}`. The script used the `v` form throughout, so **every authored vec3 in the studio deserialized to the zero vector** — the orbs' `position (0, 1.6, 1.25)` was really the origin (they spawned inside the floor), every colour was black. Also: `Set` writes an existing property and does not mint one, so `set("acoustic.*")` on a newborn silently failed (`AddProperty` is the node that grants); and `scale` is not a registered property on Object at all — `shape.r` is a Sphere's size.
    - **`seedArtCategories` had no caller in `src/`**, so Zone hydration at boot found no `category.art` and `Formation::addRelation` refused the taxonomy edge — which is how the Zone file lost 3 relations. Confirmed by running the app and reading the refusal, not inferred. Seeded now; the refusal message also used to say "self-ground or a directed cycle" for *every* refusal and now names the real cause.
  - **Every 2D control is unclickable on a HiDPI display — the 2D draw and the 2D pick are in different coordinate spaces.** Found by Zach's play-test 2026-09-02, not by reading. `draw2DObject` lays `Shape2D` rects out inside `begin2D(fbW, fbH)` from `glfwGetFramebufferSize` (`EngineRender.cpp:121-136`), so `_x2D` is in **framebuffer pixels**. `InteractionChannel::step` fills `sense.pointerX/Y` from `glfwGetCursorPos` = **window points**, computes `scaleX = fbW/winW` explicitly, and applies it **to the 3D ray only** — `observe()`'s 2D AABB test then compares unscaled window points against a framebuffer-space rect (`InteractionChannel.cpp:140-155`). On a Retina Mac every `Shape2D` draws at **half** its authored position and is clickable at **double** it. That is exactly what Zach saw: `state.studio` authored at (100,100) appearing as a red square in the top-left corner, and the HUD dock authored as a bottom strip at y=645 appearing in the upper-left quadrant — with no hit region on any of it. Worse, the phantom hit regions sit where nothing is drawn and **swallow 3D clicks** aimed at the console, since a 2D hit replaces a 3D hit unconditionally. **This breaks every `Shape2D` in the engine on every Mac, not just the Synthesis Studio.** Invisible at scale 1, which is why it survived. Fix: scale the pointer into framebuffer space once in `step()` (the factor is already computed there) and keep the window-point value for `dragTotalX`/`clickSlopPixels`, which are documented in that space. Then pick one space for `begin2D` across the tree and state it in `Renderer.hpp`'s boundary contract — `Menu.cpp:123` passes window points while `EngineRender.cpp:132` passes framebuffer pixels.
  - **`ActionNode::PlayAudio` is a stub with no listener** (`ActionModel.cpp:628-641` publishes `audio-synthesized`; `AudioSystem.cpp:123` says "we no longer subscribe" — two occurrences in the whole tree, one of them that comment). It ignores its frequency/amplitude/waveType paths *and reports `emitEffect(..., true)`*, so the audit log says the note played. Five of the studio's eleven laws are silent. The surviving path needs `acoustic.isSoundEmitter`, which nothing in the studio sets. Implement it or make it fail honestly — a lying success is the one thing `NodeOutcome` was built to prevent.

  - ✅ **Click Registration Investigation & Repair (2026-09-02):** Resolved the failure where clicks did not register on Synthesis Studio controls. Identified and fixed five core bugs:
    (1) `shape.width2D` and `shape.height2D` were bypassed during deserialization in `Serialization.cpp` (`from_json` only wrote to `_dynamicProperties` rather than updating registered `ShapeParamBridge` properties, leaving `_shapeParams` at the 100x100 default). This caused 2D HUD pads to overlap each other by 50px (C5 stealing D5 clicks, D5 stealing E5, etc.), button hitboxes to truncate, and `Text2D` captions to become 100x100 hitboxes;
    (2) `InteractionChannel::observe()` picked negative `pickPriority` objects (e.g. captions with `-1.0`), swallowing clicks;
    (3) `InteractionChannel::step()` leaked accumulating virtual cursor coordinates into 2D hit tests while `pointerLocked` was true;
    (4) **Click Invalidation across Window/Tab Switches:** When window focus changed (e.g. switching tabs/apps, clicking outside, or opening/closing ImGui windows), GLFW on macOS never delivered mouse release callbacks to the unfocused window. `InteractionChannel` was never notified of focus loss, leaving `_liveLeftDown` latched `true` indefinitely. Once `_liveLeftDown` was stuck, `_prevLeft` stayed `true`, preventing subsequent mouse presses from firing press edges (`leftPressedNow`), failing to bind `pressedId`, and causing hand motion to trigger `dragging = true` which permanently froze all subsequent click registrations across the session. Fixed by adding `InteractionChannel::onWindowFocus`, plumbing focus changes through `Engine::onWindowFocus`, and adding self-healing physical button state reconciliation (`glfwGetMouseButton`) in `step()`;
    (5) **Unintended Cursor Lock on Menu / Window Dismissal:** Pressing `M` to close the main menu forcibly re-locked the cursor (`GLFW_CURSOR_DISABLED`) even if Creator Console or other tool windows were open, and pressing `ESC` with tool windows open toggled cursor lock instead of closing the tool window. Updated `EngineInit.cpp` so tool windows remain cursor-unlocked and `ESC` closes tool windows before toggling cursor lock. Added comprehensive test coverage in `tests/law/synthesis_studio_app_test.cpp`.
