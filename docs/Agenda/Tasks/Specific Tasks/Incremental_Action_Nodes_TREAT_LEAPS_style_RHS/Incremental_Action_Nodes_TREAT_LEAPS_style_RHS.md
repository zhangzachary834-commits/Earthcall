**Incremental Action Nodes (TREAT/LEAPS-style RHS incrementality)** — Zach's observation (2026-08-28, after reading Fable 5's [Green Hills §3](../../Reflections%20on%20Earthcall%27s%20Progression/Reflections%20on%20Trajectory/Green_Hills_Population_One.md)): the Rete incrementalizes the *condition* side beautifully — `evaluateDirty()` and compiled terminals mean only changed facts re-evaluate — but the *action* side has no equivalent. A WhileTrue law whose conditions hold for 50 subjects calls `action.run()` for all 50 every frame, even when inputs haven't changed and the output would be identical. A `Set` writing `position := vec3(0,0,0)` to a subject already at `(0,0,0)` does the full path-resolve → read → compute → write → trace cycle 60 times a second; the `skipAudit` flag (`Law.cpp:464`) suppresses the *log* but not the *work*. The solution is extending the Rete's incremental principle from condition selection to action execution — what the production-system literature calls TREAT and LEAPS (Lazy Evaluation of Actions in Production Systems). Concretely: (1) **Input-dirty gating** — an action node's inputs are the property paths it reads (Map bindings, Drive input, `@event.subject` properties); if none changed since last tick, skip the node entirely. (2) **Output memoization** — cache the last value written per law-per-subject-per-path; compare before writing; the `wrote = false` trace outcome already exists, make it the fast path instead of a post-hoc observation. (3) **Map/Flow derivative shortcut** — `Map` is `p := F(bindings)`; when a binding changes, OntoMath's `ScalarForm::derivative` can compute the delta rather than re-evaluating the full piecewise. (4) **Drive input gating** — a Drive whose input is a *property* (not the world clock) that hasn't changed can skip; the architecture already distinguishes these (`ActionNode::input`, `ActionModel.hpp:192`). Together with the condition-side Rete, this would make the idle-world cost genuinely O(changes), not O(matches). The per-law-per-subject action memo is a small struct: `{input values hash, output value}`, checked before `action.run()` in the WhileTrue reactive path (`Law.cpp:1670`).
