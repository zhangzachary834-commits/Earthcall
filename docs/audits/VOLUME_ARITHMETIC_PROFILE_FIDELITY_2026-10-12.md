## The concrete experiment

[The new driver](../../scripts/volume_arithmetic_profile_experiment.py) generates a separate option-changing wrapper in a fresh external directory. It leaves [the read-only observer](../../scratch/probes/volume_metal_compile_observer.mm) and its existing driver unchanged. The generated wrapper copies `MTLCompileOptions` only when the translated source contains volume evaluators; it forwards unchanged source once and releases the copy after library creation. Other modules keep their original settings. No hook enters an app build or installed process.

Three observed profiles on Apple M5:

| Lane | mathMode | mathFloatingPointFunctions | Disposition |
|---|---:|---:|---|
| Unchanged-options control | 2 (Fast) | 0 (Fast) | byte-identical to plain renderer |
| Safe arithmetic / Fast functions | 0 (Safe) | 0 (Fast) | rejected |
| Safe arithmetic / Precise functions | 0 (Safe) | 1 (Precise) | rejected |

The actual recorded options establish these values; source labels alone are not treated as evidence. Every paired module has identical MSL SHA256 across lanes. Non-volume option pairs, MSL language version and preserve-invariance are unchanged. Altering settings for the **whole volume module** changes more than the folded scalar, including ray, noise and transport arithmetic. This test does not locate the changed operations or prove that any individual contraction caused a difference.

The fixture reads the frozen checkout `saves/zones/Northern Veil/zone.ecform` through its existing MessagePack envelope and startup MigrationRoot decode. It does not read or mutate the current live data home; this is an offscreen four-curtain fixture with no opaque geometry, not a live Engine Zone admission witness. No serialized equations or codec change. Each process warms its rendering and captures a completed fixed-clock frame; readback and compiler records make these **correctness runs**, never performance runs.
