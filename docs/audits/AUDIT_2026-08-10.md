# Audit — 2026-08-10

Scope: the recent work on ConditionModel→Rete, WebAssembly/WebGPU, OntoMath, Audio,
the nomenclature/game-strip refactors, and Formation. Branch `sync-from-earthcall-main`,
commits `fdfa335..d4f476c`.

Method: six parallel read-only auditors, one per slice, plus central build/test and
independent verification by the orchestrator of every finding marked CONFIRMED-BY-ORCHESTRATOR.
No files were modified by this audit.

**Baseline: `cmake` configure, full build, and `ctest` all exit 0 — 35/35 tests pass.**
This is not evidence of health. See §0.

---

## §0 — The finding that governs the rest

**The green test suite does not execute the new code.**

- `compileToRete` has **no test coverage at all**. `continuous_law_test.cpp` builds laws via
  `createLaw` + `setConditionModel`, and because `add()` runs *before* the condition is set,
  `_reteTerminals` is always empty and the test silently takes the old sweep path.
  `law_persistence_test.cpp` and `basic_cube_law_test.cpp` use only `Activation::OnEvent`
  laws, which never compile to Rete. `law_loop_test.cpp` hand-builds alpha nodes and never
  creates a beta node.
- **No test under `../../tests` mentions audio or `acoustic`.**
- **No test covers any of the nine new OntoMath ops**, the two new `PropertyValue`
  alternatives, or `Zone::spatialField`.
- Tests are excluded from the wasm build entirely (`CMakeLists.txt:216-259` is inside
  `if(NOT EMSCRIPTEN)`), so no wasm-specific defect can be caught by CI.

Four of the five slices audited are substantially or entirely inert at runtime, and the
suite passes anyway. Treat "35/35" as measuring the pre-existing engine, not this work.

## §1 — CRITICAL

### 1.1 Rete: alpha and beta node IDs share one numeric namespace
`Law.hpp:570-571`, `Law.hpp:524`, `Law.cpp:1909`

`_nextAlphaId{1}` and `_nextBetaId{1}` are independent counters, and
`isAlphaNode(id) { return findAlpha(id) != nullptr; }` resolves by lookup in the alpha table
alone. Beta node 1 is therefore always misread as alpha node 1.

`All(Compare(a<1), Compare(b<1))` compiles to alpha 1, alpha 2, beta 1; the law is bound to
**alpha 1**, so a being with `a=0, b=5` satisfies it. This breaks the feature the commit is
named for, deterministically, because beta ids are always ≤ alpha ids in practice.

*Fix shape: one shared counter, or a tagged node id (`{kind, index}`).*

### 1.2 Rete: state facts exist only for law-spawned beings, so loaded WhileTrue laws never fire
`Law.cpp:1371`, `ActionModel.cpp:786`, `Law.cpp:1520-1536`

`property-state` facts are asserted only on `object-created`/`relation-formed`, and the sole
publisher of `object-created` in the tree is an `ActionNode` Create/Spawn. World load, the
object tool, and `Universe::setProvider` never emit it. Every leaf alpha predicate begins
`if (!fact->isState) return false;`.

So a saved WhileTrue law loads, `_reteTerminals` is non-empty, the fast path runs,
`collectTerminalSubjects` returns `{}`, and `continue` **skips the sweep entirely**. The same
law text behaves differently depending on whether it was authored in-session or loaded from
disk — in-session it works only because `add()` runs before `setConditionModel`.

### 1.3 Audio: the subsystem is inert end-to-end, for three independent reasons
`ObjectConcept.cpp:159-163` + `:458`; `ObjectConcept.cpp:232-250` + `:470-473`; `AudioSystem.cpp:102-376`

1. `initializeConceptIdentity()` sets `_conceptId = "concept-<N>"`, and
   `getIdentifier()` returns `_conceptId`. `registerCoreConcepts` then calls
   `setObjectID("concept-sound-emitter")`, which does not touch `_conceptId`.
   `ConceptRegistry::add`/`find` both key on `getIdentifier()`, so the concept is registered
   under `concept-1` and `spawn("concept-sound-emitter")` takes the "no such concept" branch
   on every collision, forever.
2. Concept attributes are written via `setAttribute` into `_composition.attributes`, a plain
   `unordered_map<string,string>` that `buildProperties()` never exposes — so `PropertyPath`
   cannot see them. Independently, `instantiate` never copies concept attributes to newborns.
   `acoustic.isSoundEmitter` can therefore never exist on any Object.
3. `playSound`, `playSpatialSound`, `playProceduralCollisionSound`, and `playMusic` have
   **zero callers**. `setupAudioEventListeners()` is an empty stub.

Net runtime behavior: initialize a device, pin the listener to the origin each frame, scan
every object for a property that cannot exist.

**This is a stable-identifier defect** — precisely the class e5d3fc5's new warning
(`ObjectCore.cpp:221`) was added to catch. The warning fires only when no string id is set;
`ObjectConcept` sets one and *then* overrides `getIdentifier()` to return the volatile id, so
the warning is silent on exactly the case it exists for.

### 1.4 wasm: identity and crypto are stubbed to plausible-looking garbage
`SingularId.cpp:95-107`, `KeyPair.cpp:140-150`, `Claim.cpp:85-94`

The `__EMSCRIPTEN__` branches do not disable crypto; they substitute values that resemble
results:

- `SingularId::mintOpaque()` returns `bytes[i] = i` — **the same constant id on every call,
  every session, every user.** Native throws `"CSPRNG unavailable"` rather than degrade.
  `PersonMigration.cpp:175` mints zone ids this way; two zones migrated in the browser
  collide and the second silently overwrites the first.
- `Claim::issue()`'s nonce becomes `0,1,…,15` — the replay distinguisher the comment two
  lines above says it is.
- `PublicKey::verify()` returns `false` unconditionally, so `Claim::verify()` always fails and
  `FirstMoverRegister.cpp:186` always returns `Gate::GrantInvalid`. **Every First Mover grant
  is rejected in the browser build**, reported as "invalid grant" rather than "no crypto here".

"Nothing enters the world without an author… structural, not conventional" is defeated on one
platform by an `#ifndef`. The correct degraded mode is the native one: throw.

### 1.5 OntoMath: seven of nine "native spatial operations" are unimplemented, and the GPU path fabricates a value
`ScalarForm.cpp:785-795`, `SdfWgsl.cpp:221-229`

`Raycast, SDF, Gradient, LineIntegral, Union, Intersection, Difference` return `nullopt` on
CPU and emit the literal string `"0.0"` on GPU, under a comment reading *"Placeholder…
0.0 is safe fallback."*

For a signed distance function **0.0 means "on the surface"**, so an authored
`Union(sphere, box)` compiles to `fn sdfField(p) -> f32 { return 0.0; }` and the raymarcher
reports a hit at every step — the field renders as an opaque wall filling the frustum rather
than failing. `ScalarForm.hpp:50` and `ALGORITHMS_AS_LAW` §7 both require *"undefined,
`nullopt`, never a guess."* Only `Project` and `Distance` actually compute.

Related: `Gradient` is typed `Vector` but emits an `f32`, so a VectorField AST containing it
produces `fn vectorField(p) -> vec3<f32> { return 0.0; }` — a hard WGSL validation failure at
pipeline creation.

## §2 — HIGH

### 2.1 Rete: `All` discards every terminal but the first
`ConditionModel.cpp:478` — `currentLeft = terminals[0]`. `Any` legitimately returns multiple
terminals, so `All(Any(b,c), d)` silently becomes `b ∧ d`; a subject with `c ∧ d` never matches.

### 2.2 Rete: editing a condition never recompiles the network
`compileConditionsToRete` has exactly two callers (`Law.cpp:1308` in `add`, `Law.cpp:1992` in
`loadFromJson`). `LawGraphWindow.cpp` calls `setConditionModel` in ~8 places and none
recompile. `conditionsSatisfied` uses the new condition; the Rete terminals hold the old one.
Incremental and full evaluation disagree by construction.

### 2.3 Rete: OnBecomeTrue is now level-triggered — "Edges, not levels" violated
`Law.cpp:1911-1918` binds every law with `activation() != OnEvent` into the agenda, including
`OnBecomeTrue`. The agenda drain (`Law.cpp:1437-1486`) never inspects `activation()`,
`isEnabled()`, or the false→true edge — it just applies. The law fires from the drain, again
in the continuous pass, and again on every re-assert while the condition stays true.

### 2.4 Rete: the fast path drops `targets`, onset bookkeeping, and `conditionsSatisfied`
`Law.cpp:1520-1537` vs the sweep at `1542-1574`. A WhileTrue law scoped to one being applies
to **every** matching being; `time.sinceApplied` has no t=0 so `Flow`/`Drive` read a zero
clock; and anything the alpha cannot re-check reactively (a time-dependent `Compare`, a
`Fold`, a `ForAll`, a cross-being `comparePaths`) is frozen at assertion time.

### 2.5 Rete: multi-level beta joins drop matches depending on fact arrival order
`Law.cpp:759-789` — the alpha-left branch sets `betaActivated` but never writes
`newBetaTokens[beta.id]`, which the downstream node at `712-713` iterates. For
`All(hp<5, mp<5, sp<5)`, asserting in order `sp, mp, hp` leaves beta2's memory empty though all
three hold; order `hp, mp, sp` is correct. Property order from `listProperties()` decides which
you get.

### 2.6 wasm: two files guard on `EMSCRIPTEN`, which emcc does not define
`WebBindings.cpp:4`, `WebSocketClient_wasm.cpp:3`

emcc defines `__EMSCRIPTEN__`; `EMSCRIPTEN` is a build-system environment variable. b81bd49
fixed exactly this typo in three other files and missed these two. Consequences:
`WebBindings.cpp` is an **empty translation unit** — `--bind` exports nothing, so
`web_ui/app.js:11`'s feature test always fails and the page reports "Native Engine" while
running in wasm. `WebSocketClient` has **no implementation in the wasm binary** (both the
native and wasm TUs compile to nothing); it links today only because its sole caller,
`Person::requestAIAction`, is itself uncalled and gets GC'd.

### 2.7 wasm: saves succeed and vanish
`SaveSystem.cpp:286-294`. The sync-write swap is correct, but there is no IDBFS mount, no
`FS.syncfs`, and no `--preload-file` anywhere in the tree. Emscripten's default MEMFS is
in-memory: the write returns cleanly, the UI reports success, the file is gone on reload.
Against "Say what you made," this is the worst failure shape — it reports making something it
did not.

### 2.8 Audio: `Flow` integrates, but all four acoustic laws author it as assignment
`ActionModel.cpp:641-644` is explicit: `path := path + f(bindings) * dt`.
- ADSR (`DefaultPhysicsLaws.cpp:104`) writes `amplitude += (1-2t)·dt` — starting at 1.0 it
  *rises* to ~1.25 by t=0.5.
- Vibrato (`:209`) writes `frequency += (base + 20sin(...))·dt` — 880 Hz ramps to ~1320 Hz in
  half a second. A monotonic pitch sweep, not an LFO.
- Occlusion (`:170`) climbs ~366/frame unbounded.

Separately, the ADSR decay term builds `Scale(ScalarLeaf(2.22), ValueLeaf("t"))`, and
`Op::Scale` (`ScalarForm.cpp:701`) handles only `(double,vec3)`/`(vec3,double)`. Two scalars
fall through to `nullopt`, poisoning the enclosing `Sub`, so `acoustic.amplitude` is never
written for any `t`. `MathNode::typeOf` would have caught this — it has **no callers anywhere**
(`ScalarForm.cpp:472`), so every arity and type check added by that commit is dead code.

### 2.9 Audio: collision events are levels, not edges
`Physics.cpp:344-345` publishes `PhysicsCollisionEvent` unconditionally on every frame a pair
overlaps; the edge machinery at `:349,368` is used only for `contact-ended`. The new handler at
`:548-556` mints two `objects-collided` ECA events per pair per frame, and
`physics-acoustics` is `OnEvent` with no condition — a per-frame spawner. Two resting boxes
would produce ~120 Objects/second. The correct shape is a `contact-began` edge alongside the
existing `contact-ended`.

### 2.10 Formation: `resolveTopology()` dissolves any correctly-authored category
`Formation.cpp:169-174, 207-219`

Adjacency is built **only from undirected relations**. `AUTHORED_CATEGORIES.md` §2/§8
specifies both category edges (`subcategory-of`, `instance-of`) as `directed: true`. A category
Formation therefore has zero undirected edges → zero components → `validCores.empty()` →
`clearMembers(); relationMgr = RelationManager{};` — total dissolution, silently, with no
return value indicating it happened.

Latent: `resolveTopology()` and `isCoreMember()` have no callers in `../../src`, only in their own
test. But it is the API a category implementer would reach for.

### 2.11 Formation: loading a save produces one empty subformation per relation
`ZoneManager.cpp:400-403` → `Formation.cpp:320-325`. `z.formation().add(...)` runs during load,
before `Zone::syncFormationMembers` (which doesn't run until the frame loop), so
`integrateRelationTopology` finds neither endpoint and the subformation gets no members.
Because `findOrCreateRelationFormation` matches only via `findMemberByIdentifier`, an empty
subformation can never match anything again. **Set-to-set grouping is non-functional for any
world loaded from disk** — it works only for in-memory, member-first construction, which is
exactly what both tests do.

### 2.12 Formation: `Law` replaced three Formations with a raw struct — refusal #1 regression
`Law.hpp:35-50, 367-369`. fdfa335 replaced `Formation _authors/_conditions/_targets` with
`struct Law::NodeGroup { vector<Singular*>; vector<shared_ptr<Relation>>; }` — re-implementing
what `Formation` is for while stripping everything ontological: no `getIdentifier()`, no
`buildProperties()`, not a `Singular`, not addressable by law text, not in the Universe, no
provenance. `law->authors()` is no longer a being.

Gratuitous: the same commit added `Formation() = default`, so `Formation _authors;` would have
compiled. The `Form` base removal did not force this.

### 2.13 Lifetime: three confirmed use-after-free paths
- `Zone::operator=` (`Zone.cpp:123-145`) swaps `_world` and `_formation` but **not** the three
  new spatial members. Since the copy ctor does `_formation.addMember(_spatialRootObject.get())`,
  the Formation ends up holding a pointer into the destroyed temporary. Latent — no live call
  site copy-assigns a `Zone`.
- Nothing removes a destroyed Object from `Zone::_formation` (`World.cpp:135-153`,
  `Law.cpp:1689-1696`). The reaper's own comment says every Formation must let go; it covers
  `Law::NodeGroup` and other Objects' element formations, not `Zone::_formation`. A law
  destroying an attachment parent yields a use-after-free in `findMemberByIdentifier`
  **every frame for the rest of the session**.
- `_dirtyFacts` is purged by no retraction path (`Law.cpp:896-930`), so a destroyed subject's
  fact is dereferenced next tick and then re-asserted for a dead being.

Adjacent: Formation's copy constructor shallow-copies `vector<shared_ptr<Formation>> subformations`,
so a "copy" shares subformation objects with the original — contradicting its own comment that
*"a copied formation is a new being, not an alias."*

## §5 — What is genuinely clean

Verified, and these are the parts most likely to have gone wrong:

- **Save-file compatibility across the whole slice.** `ConditionNode`/`ActionModel`
  serialization was not touched; `ReteNetwork::toJson`'s schema change is safe because the Rete
  is runtime-only state with no reader; Formation's on-disk format is unchanged and needs no
  migration.
- **Bounds doctrine.** `kMaxChainRounds = 8`, `kMaxCallDepth = 32` — unraised.
- **Authorship and authority.** `Law.cpp:332` returns `Unauthored` before conditions are
  evaluated. `kAuthoredCeiling = 0`, and the file-read path (`Law.cpp:265`) goes through the
  clamping `setAuthorityLevel`, not `grantAuthority`. Hand-editing `"authority": 99` yields 0.
- **The wasm main loop.** `emscripten_set_main_loop_arg` with RAF-driven `fps=0`, correct
  cancellation, and the zero-framebuffer early-return correctly placed *before*
  `ImGui_ImplWGPU_NewFrame` — no unbalanced `NewFrame`.
- **WebGPU binding upgrade.** Every callback-info sets `.mode`; `WGPUStringView`
  construction, the canvas-selector chain, userdata lifetimes, and handle release order are all
  correct. Skipping `wgpuSurfacePresent` on wasm is right — the browser compositor presents.
- **Audio realtime-thread safety.** There is no user-written data callback anywhere, so no
  allocation, locking, I/O, logging, or `std::string` construction on the realtime thread.
  Position updates go through miniaudio's atomic setters. The one hazard is non-atomic
  multi-field `ma_waveform` mutation from the main thread (`AudioSystem.cpp:258-262`), currently
  latent because no emitter is ever created.
- **Headless audio degrades correctly** — `init` failure leaves `_initialized == false` and
  every method guards on it. Shutdown order is correct, no leaked handles.
- **`ObjectTypes.hpp` / `ObjectProperties.cpp`** — a verbatim move. Byte-equivalent property
  registration, no new enum values, no new hardcoded domain fields, no `Body` on `Object`.
- **The deleted `tests/authored_categories_probe.cpp` was a correct de-duplication**, not a loss:
  `../../scratch/authored_categories_probe.cpp` is byte-identical, tracked, and unmodified. This is
  exactly what the "Working notes" instruct. Note however that `../../scratch` is not built
  (`CMakeLists.txt:111` filters it out), so those claims are no longer executed automatically.

## §6 — Recommended order of work

1. **One regression test first.** Load a WhileTrue law with a two-clause `All` from JSON and
   tick it. That single test catches §1.1, §1.2, and §2.4 simultaneously, and would have caught
   all three before they landed.
2. **§1.1** (shared id namespace) — smallest fix, largest correctness gain.
3. **§1.2 + §2.2** — assert `property-state` on world load; recompile on `setConditionModel`.
4. **§1.4** — make the wasm crypto stubs throw like the native path rather than return
   plausible values. A browser build that cannot author is correct; one that mints colliding
   ids and rejects every grant while reporting "invalid grant" is not.
5. **§1.3 + §2.8** — the audio slice needs the concept-id fix, attribute propagation, and a
   re-reading of `Flow` before any of its laws can be evaluated for correctness.
6. **§1.5** — either implement the seven ops or make them fail loudly; the current GPU `"0.0"`
   is a wrong answer presented as a right one.

## §7 — Coverage gap in this audit

**The nomenclature/game-strip slice (`47cf2cc`, `74bae23`, `0b9e7a1`, and the naming half of
`e5d3fc5`) was NOT fully audited** — that auditor terminated on an account spend limit before
reporting. Roughly 3,750 deleted lines across those four commits have had no systematic review.

The orchestrator covered only the stable-identifier question directly (§1.3, §3), which turned
up a real defect immediately. The unexamined risks, in the order worth checking:

1. Behavior deleted but never replaced by authored law — was `LAW_MIGRATION_FRAMEWORK.md`'s
   ladder actually completed, or did migration stop at deletion?
2. Save compatibility after field removal — do files under `../../saves` still load, and are removed
   fields skipped gracefully or do they shift?
3. Renames that broke referential integrity between a C++ symbol and a string identifier, save
   field, doc reference, or test fixture.
4. Whether tests were deleted because the behavior legitimately went away or to make a red
   build green.

This slice should be re-run before the audit is considered complete.
