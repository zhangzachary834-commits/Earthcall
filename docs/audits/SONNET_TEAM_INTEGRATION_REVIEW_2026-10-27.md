## Integration corrections that made the pieces fit

1. **Surveyor → Oracle is lossless.** The original Oracle contract demanded unit directions and integer-typed pixels while Surveyor preserves recorded non-unit directions and integer-valued float pixels. The merged adapter accepts finite nonzero directions unchanged, checks integer-valued pixels, validates the Surveyor manifest and retains the original ray-file bytes/hash. Medium clock bindings must be supplied explicitly; different medium clocks still refuse because the existing reference evaluates a shared clock. This is a reference capability limit, not a new authored restriction.
2. **Reference identity is not manufactured.** The original CLI attached the selected capture's hash/pixels to arbitrary raw reference rows. A retained generation receipt is now mandatory before that binding: original ray-file and reference-byte SHA, frozen fixture SHA, time, origin, medium clocks and generator identity must agree. No receipt is synthesized from old rows plus a new capture. The receipt is provenance evidence supplied with the job, not cryptographic authentication or proof that reference mathematics is correct. Contemporary Current/build/backend identity remains the native producer's obligation; pixel alignment alone cannot establish it.
3. **Default reference path fails closed.** Surveyor keeps the empty stub only in explicitly named `diagnostic_only_harness_env`. Normal harness settings point at the real reference path, which is absent until generated. Unreferenced parity/timing cannot silently become accuracy acceptance.
4. **Capture and dispatch bounds strengthened.** Re-signed fractional-pixel edits now refuse rather than being truncated by `int()`. Python planning and C++ device guards check per-ray and worst-case indirect-producer dispatch dimensions as well as classifier dispatch. Buffer and working-set estimates remain scoped planning assumptions; no native limit/cost claim is inferred.
5. **Our replay corrected.** Actual row IDs/coverage are checked before pixel identity is attached, with missing/extra/wrong-ID controls. The PASS message prints the computed statistic count. Historical archive bytes are unchanged; its embedded old replay remains historical. K>1 parity remains stored native assertion/log evidence because those rows were not archived. Identical candidate rows across five modes are one numerical population observed through multiple execution paths, not five independent mathematical references.
6. **Guardian's Mode2 description corrected.** The actual archived6em branch is routed-unfused: reset/classify/args/S1-unfused/S2/General/unfused/Current. It is not the older streamed `fastFull` branch inherited earlier in the generator. The integration control checks the actual final source branch. Guardian's important underlying gap survives: the forced-S2 late-refusal publication audit tests terminal Mode4; equivalent native intended-capacity/refusal/publication ownership controls for winning Mode2 remain open.
