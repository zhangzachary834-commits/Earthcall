## 6. Bottleneck Migration Analysis (`KC6` Diagnostic) & The Mission for §6dh

### What Was Successfully Eliminated in §6dg:
1. **Register Bloat Eliminated:** In §6de, `cnoise3Pair` added $+10$ scalar registers. In §6dg, register streaming and `prev_rho` forwarding kept register allocation minimal without spill.
2. **LDS Synchronization Stalls Eliminated:** Zero bytes of workgroup memory and zero `workgroupBarrier()` calls in `classifyTilesMain`.
3. **18.87 MB Schedule Buffer Roundtrip Eliminated:** $S1$ and $S2$ step positive subpanels directly in registers on the fly.
4. **Sorting Loop Eliminated:** Certified non-overlapping curtains require zero multi-curtain event sorting.

### Where the Bottleneck Migrated (The §6dh Frontier):
1. **SIMD-16 vs. SIMD-32 Half-Warp Occupancy:**
   - In Apple Silicon (M5), the native SIMD execution width is **32 threads**.
   - Because our tile size is $4\times 4 = 16$ pixels, `@workgroup_size(16)` runs at **50% SIMD lane utilization** (16 active lanes, 16 completely idle lanes per warp!).
   - In `classifyTilesMain`, 1 thread per tile with 36 workgroups of 64 threads evaluates knots cleanly, but in the ray marcher passes, dispatching 16-thread workgroups halves ALU execution efficiency.
   - **Fix for §6dh:** Group $2\times 2$ tiles ($8\times 8 = 64$ rays) or $2\times 1$ tiles ($4\times 8 = 32$ rays) per workgroup to achieve **100% full-width SIMD utilization**.
2. **Multi-Pass Command Encoder State Switching:**
   - The cold routed dispatch currently encodes three separate compute passes (`cpAlpha`, `cpBeta`, `cpFallback`) sequentially.
   - On Metal, switching pipeline state objects across three passes introduces driver command buffer encoding overhead.
   - Reference Marcher runs as a single monolithic dispatch.
   - **Fix for §6dh:** Consolidate Pass 1 into a single uniform launch utilizing `dispatchWorkgroupsIndirect` or packing specialized residual tile loops into a unified multi-lane worker that avoids CPU/GPU pipeline churn.
