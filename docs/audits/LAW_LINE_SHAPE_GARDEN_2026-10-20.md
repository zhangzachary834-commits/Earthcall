## Reproduction and limits

Build the ray snapshot using `docs/BUILD_AND_ENVIRONMENT.md`, then run `python3 scratch/probes/law_line_shape_garden_probe.py --ray-root <clean-ray-checkout> --build <its-build> --native --output <report-directory>`. The runner checks ray lineage, refuses dirty source, uses separate fixture data, invokes the real compiler path and exercises the native reload. `scripts/install_law_line_shape_garden.py --dry-run` reviews prospective new roots; it never overwrites differing/inhabited semantic roots.

The installer was used only after compiler, logic and native verification. It stages each new root beside its destination, verifies bytes/parsing, rechecks absence, installs dependencies first and the Zone last. The initialized Zone/objects remain for runtime Laws to create with the real world's allocator. Whole-batch physical-terminal paste, inhabited restart, physical pointer feel, automatic cross-app Screen ownership and Zone-exit restoration are not established by these tests.
