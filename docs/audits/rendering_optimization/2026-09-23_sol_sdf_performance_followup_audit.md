### Two obligations before diagnostic proof becomes authority

The observer's O(1) source-set fast path trusts `setRevision` plus vector size, and its vessel cache keys by `(channel, raw Piecewise pointer, authored revision)`. The current Engine producer builds set revisions from `std::hash` of concatenated identifiers and per-expression revisions, themselves derived from serialized JSON (`EngineRender.cpp:137-157,173-198,207-242`). This is reasonable *diagnostic* bookkeeping under the producer's revision contract. It is not, by itself, a proof that every in-place mutation, pointer reuse, or hash collision will invalidate a future authoritative theorem. Before any pixel-changing consumer is attached, specify the semantic identity/lifetime contract and test premise mutation, removal/re-addition, allocator address reuse, and fail-open behavior across revision changes. In particular, do not let identical canonical math let a rho theorem authorize a density skip, or let zero D erase independently authored V4 medium emission. The Suns already enforce the latter distinction in their witnesses; carry that boundary into the eventual consumer.

The observer also retains `_vessels` entries and canonical literal identities until explicit `reset()`, with no ordinary eviction in this PR. This is not a measured leak or a blocker for a disabled diagnostic seam. It is a concrete long-session measurement target: record cache entries/bytes under repeated authored edits and Zone replacement, then choose a bounded or epoch-scoped lifetime before enabling observation by default in long sessions. The test-only compiler's `exactEvaluationsAvoided > proofBuilds` assertion is work-unit accounting, not a wall-clock profitability gate; once rendering authority is proposed, charge compile/repair time, branch tests, residency, and GPU divergence against actual exact evaluations saved.

## Independent finding 1 — proof availability is not proof profitability

Sol's PR #298 diagnostic used the emitted production `rangeCandidate()` on 160×100 deterministic rays. On the horizon it recorded **83,649 consultations for 144 saved exact `sdfSampleStep` calls**; at 45 degrees, **74,686 for 157**. The paired native Release path was about **1.31× / 1.40× slower** in those reported runs. PR #301 then charged hidden record tests to the proposed direct-run artifact, rejected it, and rejected the camera-independent route atlas after its horizon capture failed. These are *inherited* Sol measurements, not measurements made in this session. Their permanent record is [the direct profitability artifact](../../architecture/SDF_SPATIAL_PROPHETIC_DIRECT_PROFITABILITY_ARTIFACT.md).

The horizon ratio is roughly **581 queries per exact sample saved**; 45 degrees is roughly **476**. A useful local cost model is:

`T_on - T_off ≈ N_query · C_query - N_saved · C_exact + Δ_shader/occupancy + Δ_CPU`.

Even if the interval theorem is immaculate and the proof buffer costs zero bytes to re-upload, this path needs each consultation to cost far less than about one five-hundredth of the avoided exact evaluation before other penalties enter. That is a severe economic requirement. A positive cell may contain no zero and still save no work because the ordinary marcher would cross it in a stride, because the ray never asks there, or because discovering it costs more than the sample it replaces. The theorem knows where emptiness is; the renderer must know whether asking about that emptiness is worth the question.

This refines the September 18 complexity companion. `log H + A` is not an automatic per-ray fee. The present shader calls `rangeCandidate` again when an exact step crosses its current interval (`SdfWgsl.cpp:1640-1668`); its cost is closer to `Q · C_query + Z · E`, with `Q` *measured* and coupled to the exact marcher's trajectory. Any scene-DAG successor must account for branch visits, record tests, and divergence in the same way, rather than reporting only fewer top-level queries.

## Independent finding 2 — the default-off path has no no-feature comparator

`ScreenChannel::sdfRangeProxyEnabled` defaults to `false` (`ScreenChannel.hpp:88`). That is prudent after the slower ON verdict. But the generated WGSL contains `rangeCandidate` and the per-iteration `inst.rangeTraversalEnabled` check even when the flag is false (`SdfWgsl.cpp:1351-1445,1640-1668`). The paired OFF/ON benchmark uses the same compiled shader structure in two persistent renderer states (`webgpu_sdf_range_perf_test.cpp:2124-2125,2488-2555`). It cleanly measures the **incremental cost of activation**, not the total cost of carrying a dormant proof branch compared with a shader that has no proof machinery.

I cannot infer a default-off slowdown from source alone: Metal's compiler may lower the uniform branch cheaply, and a different shader variant also incurs pipeline costs. This is a missing comparator, not a measured regression. The next bounded test should compare three warmed Release arms on the same current field and cameras: generated shader with no proof branch, current proof-capable shader with traversal disabled, and current shader with traversal enabled. Preserve image parity, current radiance semantics, AB/BA ordering, and active-traversal/zero-upload witnesses. If the first two are equal within noise, close this question. If not, consider a structural shader variant and measure its compile time and pipeline memory before adopting it.

## Independent finding 3 — GPU residency has not removed CPU frame work

The September 18 call for persistent state was right. The current implementation avoids repeated GPU writes for unchanged parameter and proof bytes. Yet each `drawImplicit` appends `prog->params` to a CPU vector, and each traversal-enabled draw appends proof words (`WebGpuRenderer.cpp:1840-1857,1893-1901`); `flushSdfDraws` compares each aggregate against a mirror with `memcmp` and creates new bind groups (`WebGpuRenderer.cpp:2141-2287`). That is `O(Q + R + M)` style CPU copy/compare and driver work per frame even when uploads are zero. The single enormous Perlin surface is GPU dominated, so I do **not** rank this above the 581:1 query problem. It matters in the many-Object, many-structure matrix the original audit requested, and for worlds where the field evaluator is cheap enough that CPU submission dominates.

Measure CPU SDF gather time, bytes copied into parameter/proof batches, bind groups created, live cache sizes, and GPU main-pass time separately. A `sdfParameterBytesUploaded == 0` counter certifies transfer economy, not CPU quietness.

## Independent finding 4 — editing can rebuild the whole theorem synchronously

When the range flag is on, a changed `memoParameterRevision` causes `drawImplicit` to rebuild the range hierarchy, zero-set proxy, and fixed-depth bitmap in its frame path (`WebGpuRenderer.cpp:1772-1802`). `Object::invalidateFieldParameterCaches()` increments that revision for numeric edits (`ObjectCollision.cpp:199-210`). `buildRangeHierarchy` recursively evaluates each visited cell (`Sdf.cpp:681-754`). The later Sol plan explicitly allowed this whole-revision build as a correctness bootstrap; it did not claim local invalidation was complete.

This is a **potential edit hitch**, not a measured one. The proof is static across camera motion, which is good, but an authored numeric drag can make the next frame pay for the whole theorem. Record p50/p95/max frame and hierarchy-build milliseconds while editing amplitude, frequency, offset, and extent separately; assert that pure camera movement produces zero rebuilds. Only then decide whether dependency-frontier repair is worth its own complexity. `sdfRangeHierarchyBuilds` counts events but does not measure their latency.

## Independent finding 5 — the benchmark is faithful mathematics assembled twice

The native performance witness builds `y - 40·noise(0.008·(p + (100,0,100)))` in C++ (`webgpu_sdf_range_perf_test.cpp:67-103,2145-2150`) and measures it at 2880×1800. The current `NoiseFloorWorld` Zone save carries the same apparent AST and `[1000,30,1000]` extent (`saves/zones/NoiseFloorWorld/zone.json`). A separate `perlin_zone_field_restore_test` checks that the save hydrates into a Field, but does not tie the benchmark's hand-built AST to the current authored save or render the loaded Zone. Today's numbers are a strong controlled microbenchmark, with an unguarded future drift seam.

Keep the synthetic arm for stable A/B. Add a small equality/hash assertion against the hydrated canonical Zone field, and a distinct loaded-Zone native witness for any Person-facing FPS claim. This protects Zach's field from becoming a benchmark's remembered copy of it. It requires reading the save, never rewriting it.
