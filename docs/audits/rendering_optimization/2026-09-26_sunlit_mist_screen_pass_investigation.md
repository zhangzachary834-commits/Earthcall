## Source inspection at `8fbc201a`

`WebGpuRenderer::flushVolumeComposite` flushes opaque mesh and SDF draws, ends their pass, and opens a volume pass loading the existing full-resolution color. The volume pipeline reads the finished depth texture; it has no depth attachment. Its shader reconstructs a ray from `in.position.xy / u.viewport`, loads `sceneDepthTex` at the corresponding integer pixel, and clips the medium's integration to that surface. It emits premultiplied `C_medium` and opacity `alpha=1-T`; fixed-function blending computes `C_medium + T*C_scene`. It then reopens a pass loading color and depth for world overlays. The volume pipeline cache is keyed by full WGSL text.

The nested visibility loop evaluates the authored occluder SDF up to 24 times within each of 96 volume steps. At most 2,304 visibility SDF evaluations per covered pixel follow, before density and other authored expressions. At 1280×720 that ceiling is roughly 2.12 billion evaluations per full-screen medium, although early termination, coverage, and depth reduce actual work. This is an upper bound, not a measured invocation count.

The reduced-size RGB observation cannot establish final image parity. In particular, opaque edges, alpha/transmittance, and overlapping media were absent. It is retained only to localize cost, not to support a reduced-resolution path.

## V5 shared-source candidate, 2026-09-25 21:57 PDT

Zach identified a narrower exact-work hypothesis: the renderer passes the same admitted source rho/chroma/angular expression pointers to each `VolumeProgramInput`, while `compileVolumeSet` emits source coordinate and evaluator work inside each occupied medium branch. Northern Veil's saved source has AST radiance but no authored source chroma or angular expression; the latter two may compile to defaults. The candidate is therefore repeated **radial radiance** evaluation, not an assumed fourfold cost for all source channels. Sunlit Mist uses the single-medium V4 path and is unaffected.

The tested diagnostic candidate was default off (`EARTHCALL_EXPERIMENT_V5_SHARED_SOURCE=1` in a separate test process). It activated only when all source-expression pointers were identical. At the first positive-density member of each view sample, it bound member 0's parameter segment (`g_instIdx=1u`), computed the shared source factors using `u.sourceTime.x`, then restored the active member index before that medium's independent visibility, phase, extinction and emission work. On pointer mismatch it emitted the previous per-member path. Parameter blocks remained concatenated and each medium retained its own offset. The completed negative measurement below is why the candidate was withdrawn.

The experimental macOS probe emitted WGSL call-site and member-reference diagnostics and full RGBA hashes at 1280×720 for Northern Veil A–B–B–A, plus source-time and in-memory source-parameter cases. It reported synchronized wall/CPU costs and GPU timestamps when supported. The generated shader's branch gate did not prove runtime GPU work was duplicated in the baseline or saved in the candidate; the compiler could already eliminate it. Full saved-scene native-resolution image parity, moving-camera behavior, source mutation over a resident pipeline, GPU cost, and sustained responsiveness remain outstanding for any future production candidate.

## Test-only native shader work counter (pending macOS CI)

The draft PR now has a default-off `EARTHCALL_DIAGNOSTIC_VOLUME_WORK=1` mode. It replaces the volume fragment's color with two packed 12-bit counters for the **last read-back frame**: executed view samples and, for one medium, actual calls into the authored occluder SDF during source visibility. For V5, the second counter instead counts member density evaluations inside the occupied member AABB branch. The diagnostic probe decodes and sums these values over the framebuffer; it rejects counter saturation and empty view coverage. ## Single-medium source-geometry reuse candidate (default off, pending CI)

A separate bounded Sunlit Mist hypothesis targets a duplicate calculation within **one** occupied view sample. The caller computes `sourceDelta`, `sourceDist`, and `lightDir` for authored source factors; the visibility helper then computes the opposite displacement, its length, and normalized direction again before up to 24 SDF steps. The experimental `EARTHCALL_EXPERIMENT_VOLUME_REUSE_SOURCE_GEOMETRY=1` shader passes the caller's distance and direction into the single-medium visibility helper. The no-occluder shader retains its original body, and an unexpected occluder shader structure retains the original exact shader and logs the fallback; the probe requires that the saved Sunlit Mist candidate actually transformed. This does not cap steps, cull occluders, reduce drawable size, or alter saved values. V5 is untouched by this candidate.

For finite source and sample coordinates with distance above the helper's `1e-4` guard, the two displacements are algebraic opposites and the caller's `max(sourceDist, 1e-8)` divisor equals `sourceDist`. The candidate still requires a native same-camera/time **full RGBA** A–B–B–A witness: differences near floating-point boundaries or a compiler that already eliminates the duplicate could invalidate it. Focused macOS CI compares 1280×720 saved Sunlit Mist volume-only PPM **and alpha PGM bytes** at fixed and moving cameras, with synchronized wall/CPU timings. Even identical volume-only files and a speedup would not establish full saved-scene parity around objects and depth edges, GPU timing, sustained app responsiveness, or Person acceptance. This candidate is test-only until those gates are met.
