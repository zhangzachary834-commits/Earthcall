# Person Interface and Experience

The surface a Person meets is the OurVerse authorship surface — tools, chat,
controls — not a product UI. Earthcall does not have users.

## The fork

Two ways the surface can be made:

**(a) Channel.** ImGui chrome around the world. The Person's live intention
(which tool they hold, which shape, whether Create is armed) is registered
state on a first-mover channel (`CreationChannel`). Laws read those paths.
The chrome writes them; it does not hide a second copy.

**(b) In-world.** The surface is itself beings — Objects, Formations, Lexemes —
authored the same way everything else is. No ImGui taxonomy of activity
(`CreatorSection`, `Mode3D`, `Tool::Type`) deciding what kinds of doing exist.

**(a) is the path we are on.** Dispatch already left render
(`Rendering::stepCreationTools` from `Engine::update`). Console Create and L
write the same `@creation-channel.active3DMode`. That is what makes (b)
possible later without rewriting law text: the paths stay, the shell can go.

(b) is not refused. It is feature-sized item 3 / Architectural Actualization
23, and it waits on (a) being honest. Do not paint a HUD onto the wrong path
in the meantime.

## What a Person must be able to do

Find the gesture, see that it is armed, see where it lands, read back what
was born, take it back. Audit: `docs/audits/PERSON_INTERFACE_AUDIT_2026-08-18.md`.

## First movers on this surface

The Law Author's register has one bootstrap heading: **First movers**. Default
physics (`physics-gravity`, kinematics, the acoustic suite), the creation and
locomotion channels, and the shape-generator factory all belong there. A
second "physics laws" list was a second register. Authored laws appear above
that heading only once a Person writes one.

Inventory: `docs/architecture/law/FIRST_MOVER_AUTHORING.md` §1.
