## 2026-09-17 - Pointer-based Fast Path for State Fact Seeding **Learning:** `LawManager::tick()` invokes `seedStateFacts` on every `Singular` in `Universe::instance().beings()` every frame. Previously, `seedStateFacts` performed `being->getIdentifier()` (a virtual call returning `std::string` by value) and an `unordered_set<std::string>` lookup on every being per tick. **Action:** Maintain a `std::unordered_set<const Singular*> _seededBeingPointers` to provide an $O(1)$ scalar fast-path check, bypassing string heap allocations and string hashing on hot tick loops.

## 2026-09-18 - String-View Pointer Map Lookup for Vocabulary Indexing **Learning:** `LawManager::refreshVocabularyIndex()` iterates over all `beings` and their properties during index rebuilds. Previously, it constructed a temporary `std::string` per property per being to insert/lookup in `_vocabularyIndex`. Pre-populating vector pointers into a `std::unordered_map<std::string_view, std::vector<Singular*>*>` eliminates string allocations and inner-loop map lookups during index generation. **Action:** For index building loops where key sets are known prior to scanning, map `string_view` keys directly to stable target container pointers.

## 2026-09-19 - Pointer-Indexed Fast-Path for Rete State Fact Dirty Marking **Learning:** `Singular::setPropertyChangeCallback` fires on every property mutation in the engine. Calling `_rete.markFactDirty(owner->getIdentifier(), name)` performed a virtual `getIdentifier()` returning `std::string` by value, concatenated `"subjectId:attribute"` into a second temporary string, and hashed the string key in `_stateFactsBySubjectAttr`. **Action:** Index Rete state facts by `const Singular*` pointers (`_stateFactsBySubjectPtrAttr`) and pass the `Singular*` pointer directly to `markFactDirty(owner, name)`, bypassing identifier materialization, key string construction, and string-key hashing on hot property change loops.

## 2026-09-20 - O(1) Law Identifier Map Indexing **Learning:** `LawManager::find` and `LawManager::add` were performing $O(N)$ linear scans over `_laws` (`std::vector<std::shared_ptr<Law>>`) calling `law->getIdentifier()` on every element per lookup. Because `Law::getIdentifier()` returns `std::string` by value, every agenda activation drain and drive session tick was allocating temporary strings to do linear comparisons against every law in the register. **Action:** Maintain a `std::unordered_map<std::string, Law*> _lawById` index in `LawManager` synchronized on `add`, `remove`, and `loadFromJson` to give $O(1)$ constant-time law lookups and duplicate checks, eliminating vector scans and string allocations on hot tick loops.
